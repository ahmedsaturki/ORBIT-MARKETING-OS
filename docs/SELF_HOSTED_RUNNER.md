# ORBIT Self-Hosted Runner Setup

## Purpose

ORBIT uses an owned self-hosted runner as the zero-cost fallback for full verification and reproducible lockfile generation. GitHub documents repository-level self-hosted runners under **Settings → Actions → Runners → New self-hosted runner**; on Windows, the configuration shell should be elevated and the runner can be installed as a service. urlGitHub: Adding self-hosted runnershttps://docs.github.com/en/actions/how-tos/manage-runners/self-hosted-runners/add-runners

## Required runner labels

The ORBIT workflows target:

`runs-on: [self-hosted, x64]`

Keep the default `self-hosted` label and the `x64` architecture label available.

## Windows setup

1. Open the repository:
   `ahmedsaturki/ORBIT-MARKETING-OS`
2. Open **Settings → Actions → Runners**.
3. Click **New self-hosted runner**.
4. Select **Windows / x64**.
5. On the runner machine, use the commands GitHub shows for that repository. The registration token is generated by GitHub and is time-limited; do not paste it into source files, issues, or chat.
6. Install the runner as a Windows service when prompted. GitHub recommends an administrator shell for service installation.
7. Confirm the runner appears as **Idle/Online** in the repository's Runners page.

## ORBIT verification order

Run the manual workflow **Runner Probe** first.

Then, on the `rebuild/orbit-production` branch:

1. **Bootstrap reproducible lockfiles**
   - `pnpm-lock.yaml`
   - `packages/desktop/src-tauri/Cargo.lock`
2. **Full Self-Hosted Verification**
   - frozen install
   - workspace sanity
   - typecheck
   - IPC contract
   - lint
   - tests + coverage
   - runtime smoke
   - build
   - Playwright E2E
   - Rust fmt/check/test/clippy

Do not skip the bootstrap step by hand-writing a lockfile.

## Host prerequisites

The runner should have:
- Node.js 22.x
- pnpm 10.17.1
- Rust/Cargo 1.98.1
- Git
- network access to GitHub plus the package registries needed to resolve dependencies

The repository provides:
- `scripts/bootstrap-lockfile.ps1`
- `scripts/bootstrap-lockfile.sh`
- `.github/workflows/bootstrap-lockfile.yml`
- `.github/workflows/self-hosted-verify.yml`
- `.github/workflows/runner-probe.yml`

## Security

Only use a self-hosted runner for repositories/workflows you trust. GitHub warns that self-hosted runners can be exposed to code executed by workflows, so access and repository visibility should be treated as part of the runner security boundary. urlGitHub: Self-hosted runnershttps://docs.github.com/en/actions/concepts/runners/self-hosted-runners
